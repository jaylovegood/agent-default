# Codex와 Claude Code 사용 가이드

이 저장소에서는 Codex와 Claude Code를 동일한 작업자로 취급합니다. 역할을 고정하지 않고, 현재 한도가 남아 있거나 해당 작업을 더 잘 진행하는 도구를 사용하면 됩니다.

## 기본 사용

작은 작업은 다음처럼 요청합니다.

```text
Quick 모드로 이 버그를 수정해줘. 서브에이전트는 사용하지 말고 관련 테스트까지 실행해줘.
```

일반적인 기능은 다음처럼 요청합니다.

```text
Standard 모드로 구현해줘. 작업이 다른 도구로 넘어갈 수 있으니 active plan을 유지해줘.
```

보안·결제·데이터 마이그레이션처럼 위험한 작업은 다음처럼 요청합니다.

```text
Critical 모드로 진행해줘. 먼저 계획을 작성하고 구현 전 검토가 필요한 상태로 준비해줘.
```

## 다른 도구로 전환하기

현재 도구에 다음과 같이 요청합니다.

```text
다른 코딩 에이전트가 바로 이어서 작업할 수 있도록 handoff를 준비해줘.
active plan에 완료한 일, 실패한 시도, 검증 결과, 정확한 다음 단계를 기록해줘.
```

새 도구에서는 다음과 같이 시작합니다.

```text
현재 작업을 이어서 진행해줘. 먼저 AGENTS.md, active plan, 현재 diff를 읽어.
이미 완료된 조사는 근거가 충돌하지 않는 한 반복하지 마.
```

## 언어 정책

- 자동으로 읽히는 짧은 에이전트 지침은 영어로 작성되어 있습니다.
- 사용자는 한국어로 요청해도 됩니다.
- 에이전트는 별도 요청이 없으면 사용자에게 한국어로 답합니다.
- 프로젝트 문서는 해당 프로젝트에서 정한 언어를 따릅니다.

영어는 같은 내용을 표현할 때 토큰 수가 적어지는 경우가 많지만, 실제 절약 효과는 문서의 길이와 중복 제거에 더 크게 좌우됩니다. 긴 영어 문서보다 짧고 정확한 한국어 문서가 낫습니다. 이 저장소는 상시 로딩 지침만 간결한 영어로 두고, 사용자용 안내는 한국어로 분리합니다.

## 자리를 비울 때 (overnight)

자기 전이나 외출 전에 호출합니다. 작업 종류에 따라 작업 공간이 달라집니다. 시안 같은 문서 전용 작업은 main 작업 트리에 새 파일만 만들고 커밋하지 않습니다. 코드를 건드리면 같은 폴더에서 `overnight/<날짜>/<주제>` 브랜치를 파고(트리가 깨끗할 때), 미커밋 변경이 있으면 worktree를 씁니다. 브랜치/worktree에서의 커밋은 허락된 것으로 간주하며, main 커밋과 원격 푸시는 하지 않습니다.

```text
/overnight 디자인 개편 시안을 탐색해줘. 방향 3~4개, 6시간 상한. 보고서는 아침에 볼게.
```

- 시작 시 한 번만 질문합니다: 작업 큐, 시간·비용 상한, 스크린샷 도구, 권한 프롬프트 사전 허용 여부.
- 권한 프롬프트가 남아 있으면 무인 상태에서는 거기서 멈춥니다. 허용 목록을 미리 설정하세요.
- 결과는 `docs/plans/active/overnight-<날짜>-report.md`와 (코드 작업이면) 브랜치/worktree에 남습니다. 채택은 브랜치 머지, 폐기는 새 파일 또는 브랜치/worktree 삭제입니다.

## 유용한 공용 스킬

- `feature-flow`: 기능 개발 절차
- `debug-flow`: 증거 중심 디버깅 절차
- `review-diff`: 읽기 전용 변경 검토
- `handoff`: 도구 전환을 위한 인수인계 준비
- `overnight`: 자리를 비운 동안 장시간 무인 작업(디자인 방향 탐색, spikes 실험 등)

Codex에서는 `$feature-flow`처럼 호출하고, Claude Code에서는 `/feature-flow`처럼 호출할 수 있습니다.
